# 61-1

標準入力で一気にデータを入力すると次のようになりデッドロックが生じる。
1. クライアント側：read()で大量にデータを標準入力から受け取る
2. クライアント側：write()実行中。大量にデータを送信する
3. サーバ側：read()でデータを受け取る
4. サーバ側：すべてのデータを受け取る前に、write()開始
5. クライアント側・サーバー側：
    - 次のようになり、write()でブロックする。
        - 受信側：read()を実行しないため、受信側のカーネルの受信バッファが一杯になり、送信側から受け取ってもACKを返さないようになる
        - 送信側：受信側からACKが返ってこないため、送信バッファから削除できず、送信バッファが一杯になる。write()がブロックする

`受信側からACKが返ってこないため`と書いたが、受信側からウィンドウサイズが0であることを示すレスポンスが返ってくるため、送信しなくなる（こっちのほうが理由としては直接的かも？）。
